# سیاست کد، حقوق نشر و داده‌های محرمانه

این سند داخلیِ فنیِ قابل مطالعه در مخزن عمومی است؛ هیچ کلید، توکن یا داده شخصی در آن ثبت نمی‌شود.

## محل واقعی نگهداری کد
- کد روزنمای کارن: https://github.com/mckaren8089-stack/karen-rooznama
- کد کارن فیوز: https://github.com/mckaren8089-stack/karen-fuse
- مستندات و دانش مشترک: https://github.com/mckaren8089-stack/app-engineering-hub
- سه مخزن در حال حاضر `Public` هستند. کد، تاریخچه Git، بخش‌هایی از Actions و مخازن قابل Fork برای دیگران قابل دیدن/دریافت‌اند. اطلاعیه حقوق محفوظ، این دسترسی فنی را پنهان نمی‌کند.
- نسخه اجراشده وب روی GitHub Pages منتشر می‌شود. فایل‌های JS/HTML/CSS مورد نیاز مرورگر به صورت عمومی در دسترس‌اند.

## مرز حقوقی و محرمانگی
- هر سه مخزن فایل `LICENSE` با اعلان حقوق محفوظ دارند؛ این سند حق بازاستفاده آزاد مشابه MIT نمی‌دهد، اما در برابر حقوق اشخاص ثالث، شرایط GitHub و قانون اعمال می‌شود.
- هرگز رمز، توکن، API key محرمانه، فایل `.env` واقعی، کلید خصوصی، اطلاعات مالی، اطلاعات هویتی یا نسخه پشتیبان شخصی را در مخزن Public، Commit، Issue یا لاگ GitHub Actions قرار ندهیم.
- اطلاعات محرمانه برای اتوماسیون در GitHub Actions Secrets/Variables مناسب یا سامانه محرمانه مورد تأیید نگهداری شوند؛ نام متغیر می‌تواند در کد باشد، نه مقدار Secret.
- اطلاعات کاربر که در `localStorage` مرورگر است، داخل مخزن یا Action ذخیره نمی‌شود؛ پاک‌کردن Site Data و انتقال Origin ممکن است دسترسی به این اطلاعات را قطع کند. پشتیبان و بازیابی باید قبل از تغییرات پرخطر بررسی شوند.
- فایل‌های Snapshot و گزارش داخلی در Library/Google Drive، با کنترل سطح دسترسی پوشه، نگهداری شوند. وجود فایل در Google Drive **به‌خودی‌خود** به معنای رمزنگاری سرتاسری یا مجازبودن انتشار عمومی آن نیست.
- هر مخزنِ نیازمند کد واقعاً غیرقابل‌مشاهده باید Private باشد یا کد حساس در سرویس خصوصی جدا نگهداری شود. با GitHub Free، Private کردن مخزن منتشرکننده Pages می‌تواند سایت عمومی را از دسترس خارج کند؛ تصمیم مهاجرت لازم است.
- اگر اطلاعات حساس قبلاً Commit شده باشد، صرف حذف آن از آخرین نسخه کافی نیست؛ باید Secret ابطال/تعویض و سابقه دسترسی و Git history جدا بررسی شود.

## کنترل برای اپ‌های جدید
1. مجوز و حق مالکیت منابع واردشده را پیش از استفاده بررسی کن.
2. دامنه، Origin، Manifest ID، scope و نام کش Service Worker را قبل از نصب عمومی تعیین کن.
3. برای هر اپ فقط cacheهای همان اپ را پاک کن؛ هرگز `CacheStorage` کل origin را پاک نکن.
4. لینک اجرای برنامه را در ابتدای README قرار بده؛ فارسی و انگلیسی، بدون پارامتر ردیابی.
5. Release/Deploy را با آزمون کد و بررسی واقعی اجرا اعتبارسنجی کن؛ موفقیت CI تنها نشانه نصب موفق PWA نیست.
6. تغییرات حقوقی و فنی مهم را در سند مربوط ثبت کن، نه در README معرفی عمومی.
7. مجوز داده رسمی/ثالث (مثل PDF دانشگاه تهران) مستقل از LICENSE کد است.
